# Меню на неделю — список продуктов и точный план готовки

Мобильное веб-приложение: пользователь заполняет анкету, приложение собирает меню на
неделю под нормы и ограничения всех едоков, считает список продуктов и строит
пошаговый план готовки на выбранные дни.

## Что умеет

**1. Анкета (5 шагов)**

- кто ест дома: пол, возраст, рост, вес, активность, цель — суточная норма считается
  по Mifflin–St Jeor, БЖУ — от веса и цели;
- аллергии (исключаем строго, включая свои текстом) и «не люблю» (мягкий штраф) —
  отдельно для каждого едока;
- приёмы пищи, дни готовки, бюджет на неделю;
- кухня: конфорки, духовка, блендер, морозилка, контейнеры.

**2. Меню на неделю**

Неделя режется на отрезки: каждый день готовки кормит дни до следующего. Внутри
отрезка блюда подбираются так, чтобы:

- строго исключить аллергены всех едоков и рецепты, требующие недоступной техники;
- попасть в дневную норму по калориям (в тестах — коридор ±12%) и держать баланс БЖУ
  по всему дню, а не по отдельному блюду;
- не ставить блюдо позже его срока хранения: то, что не доживает в холодильнике,
  уходит в морозилку — и только если блюдо замораживается, а морозилка есть;
- не повторяться: одно блюдо максимум два дня подряд, штраф за частые повторы;
- не выдавать одно и то же из недели в неделю: из кандидатов, чьи оценки почти не
  отличаются от лучшей, блюдо выбирается жеребьёвкой.

Меню детерминировано по seed: тот же seed — то же меню. Любое блюдо можно заменить
или забанить, меню пересобирается вокруг остальных.

**3. Свои рецепты**

Экран «Мои рецепты» в профиле: название, значок, приёмы пищи, продукты из каталога с
количеством на порцию, шаги с длительностью, станцией (руками / плита / духовка /
ждём) и отметкой «занимает руки» — последнее нужно планировщику готовки. Плюс срок
хранения, заморозка и требования к технике.

Свои рецепты участвуют в подборе наравне со встроенными и при прочих равных идут
первыми, но бонус не перебивает ни аллергии, ни сильный промах по калорийности.
Редактор сразу показывает КБЖУ и цену порции и предупреждает, если порция мала или
велика для выбранного приёма пищи.

**4. Продукты**

Список собирается по задачам готовки (одно блюдо — одна готовка на все дни, которые
оно закрывает), округляется до фасовки («Греческий йогурт × 6 уп. по 130 г») и
считает сумму. Специи, соль и масло помечены как «есть дома»; любую позицию можно
переключить и пересчитать сумму.

Кнопка «Иду в магазин» открывает отдельный экран для похода: крупный шрифт, кнопки на
всю ширину, категории идут как отделы, счётчик показывает, сколько позиций и рублей
осталось. Купленное можно прятать. «Отправить» отдаёт список текстом через системный
шаринг, а где его нет — копирует в буфер. Экран старается не гаснуть (Wake Lock), но
если браузер не разрешает — просто работает дальше.

**5. План готовки**

Списочное расписание с ограниченными ресурсами: один повар, N конфорок, одна духовка.
Шаги внутри блюда идут строго по порядку, между блюдами — параллельно: пока суп
варится, руки заняты следующим блюдом. Приоритет — по самой длинной оставшейся
цепочке (критический путь). Показывает время старта каждого шага, общее время, сколько
из него руки реально заняты, что и в каком количестве отправить в морозилку.

Ручные шаги растягиваются на количество порций сублинейно (×1.9 на 4 порции, максимум
×2), пассивное время — варка, духовка, расстойка — не меняется.

## Данные и перенос

Всё хранится в `localStorage` того браузера, где заполнялась анкета — сервера нет.
Поэтому данные не переезжают сами: другой браузер, приватное окно или встроенный
браузер мессенджера — это отдельное хранилище, и анкету там пришлось бы вводить заново.

Два решения:

- **Установить приложение на телефон.** Открыть сайт в обычном браузере и добавить на
  домашний экран: приложение получает собственное постоянное хранилище и работает
  офлайн (манифест + service worker с кэшем).
- **Ссылка с данными.** Профиль → «Ссылка с данными»: анкета и свои рецепты пакуются
  в хвост ссылки после `#`. Открыли её на другом устройстве — профиль перенёсся, хвост
  сразу стирается из адресной строки. Фрагмент ссылки не уходит на сервер, но остаётся
  в истории браузера и в буфере обмена, а внутри — вес, рост и аллергии: публиковать
  такую ссылку не стоит. В интерфейсе об этом написано.

## Стек

React 18 + TypeScript + Vite, без бэкенда: состояние живёт в `localStorage`.

```bash
npm install
npm run dev        # дев-сервер
npm run test       # 38 тестов на алгоритмы
npm run typecheck
npm run build
```

## Деплой

`.github/workflows/ci.yml` — на каждый PR и push в `main`: typecheck, тесты, сборка.
`.github/workflows/deploy.yml` — на push в `main` собирает и публикует `dist` на
GitHub Pages. Сборка идёт с относительными путями (`base: './'`), поэтому одинаково
работает и локально, и в подпапке репозитория на Pages.

Источник Pages в настройках репозитория — **GitHub Actions**
(Settings → Pages → Build and deployment → Source): workflow собирает `dist` и
публикует его через `upload-pages-artifact` / `deploy-pages`.

Два условия, без которых это не работает: репозиторий должен быть публичным (на
бесплатном тарифе Pages для приватных недоступны), а сам Pages-сайт должен уже
существовать — создать его из workflow нельзя, `GITHUB_TOKEN` получает
`Resource not accessible by integration`.

Приложение открывается по адресу `https://vyshka1.github.io/Food/`.

## Структура

```
src/
  data/ingredients.ts   108 продуктов: БЖУ, цена, фасовка, аллергены, теги
  data/recipes.ts       78 рецептов: продукты на порцию, шаги со станциями и таймингом
  data/recipeRegistry.ts  встроенные рецепты + свои из localStorage в одном пуле
  lib/nutrition.ts      нормы (Mifflin–St Jeor), доли приёмов пищи, БЖУ и цена рецепта
  lib/menu.ts           отрезки готовки, подбор блюд, хранение/заморозка, задачи готовки
  lib/shopping.ts       список покупок с фасовкой и ценами
  lib/cookingPlan.ts    планировщик с ограниченными ресурсами (повар, конфорки, духовка)
  screens/              анкета, меню, план готовки, продукты, свои рецепты, профиль
```

## Ограничения

- Цены — усреднённые справочные, не подтягиваются из магазинов.
- Нормы для детей до 18 лет — возрастные ориентиры, а не расчёт по формуле.
- При жёстких сочетаниях ограничений выбор сужается: без лактозы остаётся 54 рецепта
  из 78, без лактозы и глютена одновременно — 47. Калорийность при этом держится,
  но доля жиров в отдельные дни поднимается до ~40%.
