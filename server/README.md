# Служба разбора рецептов по ссылке

Приложение — статический сайт на GitHub Pages. Обратиться из браузера к чужому
домену оно не может: там и чужой источник, и вход по логину. Эта служба
открывает ссылку вместо него и отдаёт текст рецепта. Разбирает текст всё равно
приложение — тем же кодом, что и при вставке руками.

Служба ничего не хранит и ничего не знает о людях: получила ссылку — вернула
текст.

## Что нужно

- Node.js 18 или новее (используется встроенный `fetch`), зависимостей нет.
- Для роликов из соцсетей — `yt-dlp`. Без него ссылки на блоги работают, а
  ссылки на ролики отвечают «не нашлось текста рецепта».
- HTTPS. Приложение живёт на `https://`, и браузер **не отправит** запрос к
  службе без действующего сертификата — молча, ещё до отправки.

## Запуск

```
PORT=8080 ORIGIN=https://vyshka1.github.io node server/index.mjs
```

| Переменная | Зачем |
|---|---|
| `PORT` | порт (по умолчанию 8080) |
| `ORIGIN` | каким сайтам разрешено обращаться, через запятую. Не задан — браузер не пустит ни один запрос |
| `YTDLP` | путь к `yt-dlp`, если он не в `PATH` |

Проверка, что живо: `curl https://food.altum-it.ru/health` → `{"ok":true}`

## Как поставить насовсем (systemd)

`/etc/systemd/system/food-extract.service`:

```ini
[Unit]
Description=Разбор рецептов по ссылке
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/food
ExecStart=/usr/bin/node /opt/food/server/index.mjs
Environment=PORT=8080
Environment=ORIGIN=https://vyshka1.github.io
Restart=always
# служба ходит в интернет по чужим ссылкам — держим её в тесной коробке
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true

[Install]
WantedBy=multi-user.target
```

```
sudo systemctl daemon-reload && sudo systemctl enable --now food-extract
```

## Сертификат и проксирование

Служба слушает обычный HTTP на 8080 — HTTPS завершает веб-сервер перед ней.

nginx, `/etc/nginx/sites-available/food.altum-it.ru`:

```nginx
server {
    server_name food.altum-it.ru;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

Затем сертификат — одной командой, она же настроит продление:

```
sudo certbot --nginx -d food.altum-it.ru
```

## Что служба делает с чужой ссылкой

Ссылку присылает кто угодно, а идёт по ней сервер — изнутри сети, где у него
есть доступ к соседям и к служебным адресам машины. Поэтому:

- в частные сети (`127.*`, `10.*`, `192.168.*`, `172.16–31.*`, `169.254.*`,
  `::1`, `fd00::/8`) запросов нет вовсе, и решается это до запроса;
- ходим только по `http` и `https`: `file:` прочитал бы файлы самого сервера;
- перенаправления разбираются вручную, и каждый шаг проверяется заново — иначе
  чужой сайт увёл бы запрос на внутренний адрес уже после проверки;
- ответ читается не больше 3 МБ и не дольше 15 секунд;
- с одного адреса — не больше 20 запросов в минуту.

Отказ не объясняет причину: подробность рассказала бы о нашей сети больше, чем
нужно.

## Про Instagram

Скачивание из Instagram нарушает их правила пользования, и они регулярно ломают
такие обходы. Служба будет иногда переставать понимать ссылки на ролики и
требовать обновления `yt-dlp`. Вставка текста руками работает всегда и ни от
чего не зависит — это основной путь, а ссылка лишь избавляет от копирования.
