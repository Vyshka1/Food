# Приложение и служба на своём сервере

Здесь два дела: выложить приложение на `food.altum-it.ru` и поднять рядом
службу, которая открывает ссылки на рецепты.

Служба нужна потому, что приложение — статический сайт: обратиться к чужому
домену из браузера оно не может, там и чужой источник, и вход по логину. Служба
открывает ссылку вместо него и отдаёт текст. Разбирает текст всё равно
приложение — тем же кодом, что и при вставке руками.

Оба живут на одном адресе, и это не только удобство. Пока приложение было на
GitHub Pages, а служба на своём домене, браузер считал их разными сайтами:
нужен был список разрешённых источников и предварительные запросы. На одном
адресе всего этого нет.

Служба ничего не хранит и ничего не знает о людях: получила ссылку — вернула
текст.

## Как выложить, по шагам

```bash
# 1. Забрать проект (один раз)
sudo mkdir -p /opt/food && sudo chown "$USER" /opt/food
git clone https://github.com/Vyshka1/Food.git /opt/food
cd /opt/food

# 2. Собрать приложение и прогнать проверки
./server/deploy.sh

# 3. Настроить nginx
sudo cp server/nginx.conf.example /etc/nginx/sites-available/food.altum-it.ru
sudo ln -s /etc/nginx/sites-available/food.altum-it.ru /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# 4. Сертификат — она же настроит продление и перенаправление с http
sudo certbot --nginx -d food.altum-it.ru

# 5. Службу — как постоянную (см. ниже), затем ещё раз ./server/deploy.sh
```

После этого `https://food.altum-it.ru` открывает приложение, а
`https://food.altum-it.ru/api/health` отвечает `{"ok":true}`.

Обновление потом — одна команда: `./server/deploy.sh`. Он забирает изменения,
прогоняет проверки, собирает и перезапускает службу; если проверки не прошли,
сборка не заменится.

## Что нужно

- Node.js 22 или новее. Самой службе хватило бы восемнадцатой — она без
  зависимостей и пользуется встроенным `fetch`, — но сборка приложения на
  сервере прогоняет тесты, а те требуют двадцать вторую.
- Для роликов из соцсетей — `yt-dlp`. Без него ссылки на блоги работают, а
  ссылки на ролики отвечают «не нашлось текста рецепта».
- HTTPS. Приложение живёт на `https://`, и браузер **не отправит** запрос к
  службе без действующего сертификата — молча, ещё до отправки.

## Запуск службы вручную

```
PORT=8080 node server/index.mjs
```

| Переменная | Зачем |
|---|---|
| `PORT` | порт (по умолчанию 8080) |
| `ORIGIN` | нужен, только если приложение живёт на другом домене: список сайтов через запятую. При выкладке на свой сервер не нужен — адрес один |
| `YTDLP` | путь к `yt-dlp`, если он не в `PATH` |

Проверка, что живо: `curl http://127.0.0.1:8080/health` → `{"ok":true}`

## Как поставить насовсем (systemd)

`/etc/systemd/system/food-extract.service`:

```ini
[Unit]
Description=Разбор рецептов по ссылке
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/food
ExecStart=/usr/bin/node /opt/food/server/index.mjs
Environment=PORT=8080
Restart=always
# служба ходит в интернет по чужим ссылкам — держим её в тесной коробке
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true

[Install]
WantedBy=multi-user.target
```

```
sudo systemctl daemon-reload && sudo systemctl enable --now food-extract
```

Служба слушает обычный HTTP на 127.0.0.1:8080 — снаружи к ней напрямую не
достучаться, всё идёт через nginx, который и завершает HTTPS. Готовый конфиг
лежит в `server/nginx.conf.example`.

## Что служба делает с чужой ссылкой

Ссылку присылает кто угодно, а идёт по ней сервер — изнутри сети, где у него
есть доступ к соседям и к служебным адресам машины. Поэтому:

- в частные сети (`127.*`, `10.*`, `192.168.*`, `172.16–31.*`, `169.254.*`,
  `::1`, `fd00::/8`) запросов нет вовсе, и решается это до запроса;
- ходим только по `http` и `https`: `file:` прочитал бы файлы самого сервера;
- перенаправления разбираются вручную, и каждый шаг проверяется заново — иначе
  чужой сайт увёл бы запрос на внутренний адрес уже после проверки;
- ответ читается не больше 3 МБ и не дольше 15 секунд;
- с одного адреса — не больше 20 запросов в минуту.

Отказ не объясняет причину: подробность рассказала бы о нашей сети больше, чем
нужно.

## Про Instagram

Скачивание из Instagram нарушает их правила пользования, и они регулярно ломают
такие обходы. Служба будет иногда переставать понимать ссылки на ролики и
требовать обновления `yt-dlp`. Вставка текста руками работает всегда и ни от
чего не зависит — это основной путь, а ссылка лишь избавляет от копирования.
